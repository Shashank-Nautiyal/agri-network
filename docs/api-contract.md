# API Contract — KhetSaathi Digital Agriculture Network


**Naming convention:** camelCase on the wire (JSON). The Python side
achieves this via Pydantic field aliases (`Field(..., alias="districtId")`
+ `response_model_by_alias=True`); the Java side uses plain camelCase
field names, which Jackson handles natively.

---

## Shared objects

### Location
```json
{
  "country": "India",
  "state": "Uttarakhand",
  "district": "Dehradun",
  "latitude": 30.3165,
  "longitude": 78.0322
}
```
`latitude`/`longitude` come from the browser's Geolocation API.
`country`/`state`/`district` come from a manual field at farmer
registration (not reverse geocoding — avoids a billed geocoding API).
The `country` field and this whole schema being country-agnostic is
deliberate: the challenge rules require solutions to be designed for
cross-border applicability across BRICS nations, not just India.

### SoilData
```json
{
  "ph": 6.5,
  "nitrogen": 40.0,
  "phosphorus": 25.0,
  "potassium": 30.0,
  "organicCarbon": 0.8,
  "moisture": 22.0
}
```
Optional in `/regenerative-advice` — when omitted, the AI service
estimates pH, nitrogen, organic carbon, and moisture from SoilGrids for
the given coordinates. Phosphorus/potassium aren't available from that
source and stay `null`.

## Endpoints hosted by the AI service (called by the backend)

### `POST /diagnose`
Request:
```json
{ "imageBase64": "...", "districtId": "dehradun", "farmerId": "f1" }
```
Response:
```json
{
  "disease": "Early Blight",
  "confidence": 0.87,
  "treatmentAdvice": "...",
  "language": "en",
  "isValidImage": true
}
```
Uses Gemini multimodal vision. `isValidImage` is `false` for
blurry/non-plant images or any processing failure — the backend uses
this to decide whether to count the report toward district disease
trend data. Always returns 200, even on failure (graceful fallback with
`isValidImage: false`).

### `POST /advisory`
Request:
```json
{
  "farmerId": "f1",
  "location": { "country": "India", "state": "Uttarakhand", "district": "Dehradun", "latitude": 30.3165, "longitude": 78.0322 },
  "cropType": "wheat"
}
```
Response:
```json
{
  "recommendation": "...",
  "ndviSummary": "NDVI: 0.18 (stressed vegetation)",
  "soilSummary": "...",
  "weatherRisk": "...",
  "diseaseRiskLevel": "moderate",
  "confidence": 0.75,
  "language": "en"
}
```
Backed by real data: NDVI from Google Earth Engine (Sentinel-2), live
forecast from OpenWeatherMap, and a soil estimate from SoilGrids — all
three are fetched and reasoned into a single recommendation by Gemini.
`cropType` is optional. Always returns 200; any individual data source
failing degrades to general guidance for that part rather than erroring
the whole request.

### `POST /regenerative-advice`
Request:
```json
{
  "farmerId": "f1",
  "location": { "country": "India", "state": "Uttarakhand", "district": "Dehradun", "latitude": 30.3165, "longitude": 78.0322 },
  "soilData": { "ph": 6.5, "nitrogen": 40.0, "phosphorus": 25.0, "potassium": 30.0, "organicCarbon": 0.8, "moisture": 22.0 },
  "cropType": "wheat"
}
```
`soilData` is optional — omit it to use the SoilGrids-estimated fallback
instead of farmer-submitted lab data.

Response:
```json
{
  "practices": ["cover cropping", "crop rotation"],
  "reasoning": "...",
  "expectedBenefit": "..."
}
```

### `POST /voice-query`
**Billing-free, transcript-based — not raw audio.** STT/TTS happen
client-side via the browser's Web Speech API.

Request:
```json
{ "transcript": "What should I plant this season?", "farmerId": "f1", "languageHint": "hi-IN" }
```
Response:
```json
{ "transcript": "...", "responseText": "...", "responseAudioBase64": null, "language": "hi-IN" }
```
`responseAudioBase64` stays `null` — TTS happens in the browser.
`responseText` is generated by Gemini directly in the requested
language (no separate Translation API).

### `GET /health`
```json
{ "status": "ok", "service": "agri-ai-service" }
```

### `GET /schema` (AI-service-only, not called by the backend)
Standalone endpoint proving the country-agnostic data model for the
cross-border/BRICS interoperability requirement — not part of the
backend's integration, demoable directly via `/docs`.

## Endpoints owned by the Java backend only (not the AI service)

### `POST /api/farmers`, `GET /api/farmers/{id}`
Farmer profile registration/lookup — stored in Firestore.

### `GET /api/district/{districtId}/regional-alerts`
```json
{ "Early Blight": 3, "Leaf Rust": 1 }
```
Aggregates anonymized diagnosis records the backend has collected (from
`/api/diagnose` calls), grouped by disease name within a district. Only
reports with `isValidImage: true` are counted. This is the visible proof
of the "digital public good / scales across states" requirement.

## Reliability notes

- Every AI-service endpoint returns 200 with a graceful fallback rather
  than a 4xx/5xx error for malformed input or external API failures
  (Gemini, Earth Engine, weather, soil).
- All Gemini calls use `thinking_level: LOW` to keep latency reasonable
  (the model's default `HIGH` reasoning added 10–20s per call).
- Weather is sourced from OpenWeatherMap's classic free endpoints (not
  Open-Meteo, which hit persistent 429s on Render's shared IPs; not
  OpenWeatherMap's One Call 3.0, which requires a card even for its free
  tier).

## Change log

- Adopted full `Location` object (lat/long + manual district/state) in
  place of a bare `districtId` string, for `/advisory` and
  `/regenerative-advice`. `/diagnose` still uses `districtId` directly.
- Added `/regenerative-advice`; `soilData` optional with a SoilGrids
  fallback.
- `/advisory` backed by real Earth Engine NDVI, real weather, and real
  soil estimate — not placeholder text.
- Added `isValidImage` to `/diagnose` response so bad photos don't
  pollute regional-alerts data.
- Swapped weather provider from Open-Meteo to OpenWeatherMap (classic
  free endpoints) due to persistent rate-limiting on Render.
- Confirmed voice stays transcript-based (billing-free), not raw audio.
- Confirmed regional-alerts stays a Java-backend-only responsibility,
  now backed by Firestore instead of in-memory storage.
- Added `/schema` as an AI-service-only endpoint for the BRICS
  cross-border interoperability requirement.
